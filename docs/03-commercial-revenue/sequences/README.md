# Outreach Sequence Templates

> **HARD RULE — vetted claims only.** Every factual claim about your product in any sequence file must appear verbatim-or-cited in `docs/04-marketing/content-ops/claims-vetted.md`. If it isn't there, it doesn't go in an email. The copy-evaluator rubric (D2) enforces this at generation time; this rule enforces it at authoring time.

These are **shell templates**: they define structure, cadence, tokens, and rules. They contain no product copy. When instantiating for your company, write the copy blocks in each file — sourcing every claim from the vetted list — and keep the structure intact.

Templates contain no named prospects — all personalization is injected by the sequence-enrollment agent at send time from the enriched lead record.

## Sequence cadence

| File | Day | Channel | Sender persona |
|---|---|---|---|
| `touch-1.md` | Day 0 | Email | Founder voice |
| `touch-2.md` | Day 4 | Email | Sales voice |
| `touch-3.md` | Day 9 | LinkedIn | Founder voice |
| `touch-4.md` | Day 15 | Email | Sales voice |
| `nurture-21d.md` | Post-sequence, every 21 days | Email | Founder voice |

Sender personas map to `company-profile.yaml` → `people[]` entries with `sender_persona: true`. If only the founder is a sender, all touches go out under the founder — vary tone per the per-file guidance, not the identity.

## Personalization tokens

The enrollment agent replaces these tokens from the enriched lead record. **Every token value must trace to an enrichment field** — the copy-evaluator hard-fails hallucinated personalization.

| Token | Source |
|---|---|
| `{{first_name}}` | Contact first name from enrichment |
| `{{contact_title}}` | Contact title, verbatim from enrichment — never invent seniority |
| `{{company}}` / `{{company_name}}` | Company name |
| `{{company_description}}` | 1-sentence description of what the company does (agent-written from enrichment) |
| `{{signal}}` | The specific timing/pain signal that qualified this lead (funding, hire, launch, stated pain) — cite the enrichment field |
| `{{pain_point}}` | Segment-specific pain framing (see per-template guidance blocks) |
| `{{vertical_proof}}` | Segment-relevant proof point — must come from `claims-vetted.md` |
| `{{sender_name}}` / `{{sender_title}}` | From the `people[]` entry for the sending persona |
| `{{unsubscribe_link}}` | Generated by the send infrastructure — required in every email |

## Voice rules (instantiate from `docs/02-brand/`)

- Start with *their* context, never "I'm reaching out because..."
- Never send the same framing twice — touch-2 and touch-4 escalate specificity
- Subject-line pattern: `[their product/use case] — [the gap you close]` (founder voice) or a direct benefit statement (sales voice)
- Lead with the pain your ICP doc says is primary; don't bury it under feature lists

## Anti-spam rules (enforced by the enrollment agent before activation)

- No ALL CAPS words in subject
- No `!` in subject
- No spam trigger phrases: "free trial", "guaranteed", "act now", "limited time", "click here", "make money"
- Subject length ≤ 60 characters
- Body ≤ 250 words for touch-1; shorter for later touches (see per-file limits)
- ≤ 2 em-dashes per email (copy-evaluator E3 hard-blocks at 3+)
- Every email carries an unsubscribe line; any reply — including "not interested" — pauses the contact's sequence immediately
- Respect `SEQUENCES_PAUSED`, the suppression list, the daily send cap, and the send window in `company-profile.yaml` → `sending`

## Updating copy

Edit these template files directly — the enrollment agent reads them at runtime, so changes take effect on the next run. Submit as a PR per the standard review process. Changes to claims require the claim to land in `claims-vetted.md` first.
